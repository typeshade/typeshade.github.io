번들러는 JS를 압축하지만, `gl.shaderSource` / `createShaderModule`에 넘기는 셰이더
텍스트에는 손대지 않습니다. 배포 시점 변환은 Vite나 Webpack과 같은 방식으로 구성됩니다.
이름 붙은 플러그인을 담은 `{ plugins: [...] }` 묶음이 그것이며, (린트·측정 도구를 위한
`/dev`처럼) 자신만의 서브패스에 따로 놓입니다. 핵심 생성 경로는 중립적인 플러그인
접점(`EmitPlugin` / `EmitOptions`)만 지니므로, 이 서브패스를 한 번도 가져오지 않고
런타임에 생성 기능만 쓰는 소비자는 이 코드를 번들에 단 한 바이트도 포함하지 않으며,
일반 생성 결과는 바이트 단위로 동일하게 유지됩니다.

```ts
import { mangle, minify, obfuscate } from '@xgis/shader-dsl/emit-prod'

const renames = new Map<string, string>()
const wgsl = emitModule(m, { plugins: [mangle({ renames }), minify()] })
// obfuscate() is the standard [mangle, minify] preset:
const vs = emitGlslModule(m, 'vertex', { plugins: obfuscate() })
// …and `parens: 'minimal'` is the third axis — the smallest shipped shader:
const fs = emitGlslModule(m, 'fragment', { parens: 'minimal', plugins: obfuscate() })
```

- **`parens: 'minimal'`**: `EmitOptions`의 필드입니다. 괄호를 넣을지는 생성 시점에
  내리는 결정이기 때문입니다. IR이 이미 정확한 연산자 우선순위를 알고 있으므로, 이미
  생성된 텍스트를 다시 손보는 작업과는 다릅니다. 기본값 `'full'`은 지금까지의 바이트를
  그대로 지키므로, 요청하지 않는 한 커밋된 골든 파일과 구워 넣은 아티팩트는 전혀
  건드리지 않습니다. `'minimal'`은 WGSL과 GLSL ES 3.00이 우선순위를 똑같이 정의하는
  자리에서만 괄호를 생략합니다. 우선순위는 `* / %`가 `+ -`보다 높고, `+ -`가 단항
  `-`보다 높은 순서입니다. 관계·논리·비트·시프트 연산자는 일부러 괄호를 남겨 둡니다.
  WGSL은 이들 사이에 연쇄 우선순위를 아예 정의하지 않으므로(괄호 없이 섞어 쓰면 그쪽에서는
  컴파일 오류가 됩니다), 순위를 매기는 순간 한쪽 타깃에는 없는 규칙을 새로 만들어 내는
  셈이기 때문입니다. 재결합은 결코 하지 않습니다. `a + (b + c)`는 괄호를 그대로
  유지하는데, 부동소수점에서는 이 값이 `a + b + c`와 다른 수이기 때문입니다.

- **`mangle({ renames? })`**: Vite 스타일 팩토리인 `EmitPlugin`입니다. 헬퍼 함수
  이름, 일반 구조체 이름, (주입되는 `df64_*` 라이브러리를 포함한) 모듈 상수, 그리고
  **헬퍼 함수의 매개변수와 지역 변수 전부**를 `a`, `b`, … `aa` 같은 base-52 짧은
  이름으로 바꿉니다. 함수 범위의 이름은 함수마다 같은 이름 풀에서 다시 시작하므로, 알파벳
  앞쪽 짧은 이름을 세어 나가는 대신 계속 재사용합니다. 바이트를 줄이는 지점이 바로
  여기입니다. 실제로 배포되는 텍스트에서 식별자 비용이 가장 컸던 것은 옵티마이저
  자체의 `_cse0`/`_v0` 같은 기계 이름이었습니다. 모듈 단위로는 결정적입니다. (호출이
  분리된) GLSL의 두 스테이지 생성은 항상 같은 이름에 합의하므로, 프로그램은 여전히
  링크됩니다. `renames`에 `Map`을 넘기면 작성한 이름 → 생성된 이름 관계를 받을 수
  있습니다. 이것이 프로덕션 드라이버 로그와 GPU 캡처를 해독하는 셰이더 "소스 맵"이며,
  함수 범위 항목은 `authoredFn.authoredName` 형태의 키를 가집니다. 이 맵은 배포
  번들 밖에 두어야 합니다.
- **`minify({ numbers? })`**: 생성된 문자열을 압축하는 `EmitPlugin`입니다. 텍스트를
  토큰 단위로 분석한 뒤 토큰 스트림을 다시 생성하며, 최장 일치 규칙(maximal munch)이
  경계를 합쳐 버릴 자리에만 구분자를 하나 남깁니다. `a- -b`는 공백을 유지하고,
  `)->f32`와 `a=b*c`는 공백을 잃는 식입니다. 이는 실제 컴파일러가 쓰는 것과 같은
  규칙이므로 별도의 예외 처리가 필요 없습니다. 주석(`//`와 `/* */`)은 사라지고, `#`
  지시문은 자기 줄을 그대로 지킵니다. 숫자 리터럴은 손실 없이 정규화됩니다. `0.500`
  → `.5`, `1.0` → `1.`, `1.0e-07` → `1e-7`처럼 바뀌며, 고정 표기가 자릿수 채우기로
  손해를 보는 자리는 지수 표기로 옮겨 갑니다(`.0001` → `1e-4`, `1000000.` →
  `1e6`). 소수점만 움직이므로 정확한 변환이고, 가수 숫자는 하나도 버려지지 않으며,
  지수가 없는 실수는 언제나 `.`을 남깁니다(`1.0` → `1.`이지, WGSL에서는 정수를 뜻하는
  `1`이 되는 일은 없습니다). `{ numbers: 'f32' }`를 주면 한 걸음 더 나아가, 같은
  f32 값으로 반올림되는 가장 짧은 십진수로 각 실수를 다시 씁니다. `0.800000011920929`는
  `fround(0.8)`의 f64 출력값일 뿐이고, `.8`도 같은 비트를 담습니다. 이 변환이 정확한
  이유는, f32 컨텍스트의 십진 실수 리터럴은 컴파일러가 어차피 f32로 반올림하고, 이
  생성기의 `lit()`는 bool / i32 / u32 / f32만 표기하기 때문입니다. 다만 이는 컨텍스트에
  대한 주장이므로, `f16`을 다루는 셰이더에서는 이 모드가 물러나고 손실 없는 정규화만
  적용됩니다. `obfuscate()`가 이 모드를 사용합니다. 손으로 확인한 기준과 비교(diff)할
  때는 `{ numbers: false }`를 넘겨 리터럴을 생성된 그대로 둘 수 있습니다.
  [`minifyShaderText`](./src/core/emit-minify.ts)는 이미 문자열을 들고 있을 때 감쌀
  수 있는, 이 동작의 원시 함수입니다.
- **`inline()`**: 호출 그래프를 평평하게 펴는(난독화) `EmitPlugin`입니다. 안전하게
  인라인화할 수 있는 헬퍼는 모두 호출 지점마다 인라인되어 사라집니다. `return` 한
  번으로 끝나는 헬퍼는 표현식 치환으로 인라인되고, `let`/`var`로 시작하는 준비 구문
  뒤에 `return` 하나로 끝나는 여러 문장짜리(선형) 헬퍼(예: value-noise 함수)는 그
  문장들을 호출자 쪽으로 끌어올려 인라인됩니다. 셰이더 코드는 순수하므로 계산을 블록 앞쪽으로 끌어올려도
  결과가 달라지지 않기 때문에 이 방식이 성립합니다. `df64_*` 라이브러리, 진입점,
  재귀 함수, 그리고 제어 흐름이나 for 헤더에서 호출되는 헬퍼는 손대지 않습니다.
  크기를 줄이는 수단은 아닙니다. 여러 곳에서 호출되는 헬퍼는 호출 지점마다
  복제되기 때문입니다(뒤이은 `minify()`가 공백을 다시 회수합니다). 목적은 읽는
  사람이 따라갈 수 있는 구조 자체를 없애는 데 있습니다. 옵트인이며 `obfuscate()`에는
  포함되지 않으므로, 기존 출력은 전혀 바뀌지 않습니다. `mangle()`보다 앞에 두어야
  합니다: `{ plugins: [inline(), ...obfuscate()] }`.
- **`prune()`**: 중복된 GLSL 전방 선언을 제거하는 `EmitPlugin`입니다. GLSL 백엔드는
  함수 섹션이 의존성 순서대로 놓인다고 보장할 수 없으므로 모든 헬퍼에 대해 전방
  선언을 하나씩 내보내는데, 이 패스는 정의 자체가 이미 사용되는 모든 자리에서 함수를
  선언하는 경우만 골라 지웁니다. 이 텍스트 안에 정의가 없는 경우(외부에 정의된 함수),
  정의보다 앞서 호출되는 경우, 이 패스가 알아보지 못하는 선언 형태처럼, 그 밖의 모든
  경우는 그대로 남겨 둡니다. WGSL에서는 아무 일도 하지 않습니다. 모듈 범위 선언을
  순서와 상관없이 해석하며 전방 선언 구문 자체가 없기 때문입니다. 실제 페이로드에서는
  이 패스 하나만으로도 성과가 있습니다. df64 라이브러리와 투영 그래프를 끌어들이는
  프로덕션 변환 지도 셰이더 코퍼스에서 22_268자 / 487줄 중 **3.0%**를 차지합니다.
  예제 코퍼스에서는 거의 드러나지 않으며, 실제 코퍼스를 재 봐야만 발견되는 이유가
  여기에 있습니다.
- **`aliasTypes()`**: 자주 쓰이는 타입 하나하나에 한 글자짜리 이름을 붙이고 한 번만
  선언하는 `EmitPlugin`입니다. WGSL에서는 `alias A=vec2<f32>;`, GLSL에서는
  `#define A vec2`로 선언합니다. 두 타깃 모두 그 타입이 등장하는 모든 자리에서 짧은
  이름을 받아들이며, 생성자 위치(`A(1.,2.)`)도 예외가 아닙니다. 실제 Tint와 실제
  ANGLE로 확인했습니다. 이는 `mangle()`이 손대지 못하는 유일하게 무게가 큰 어휘입니다.
  두 언어 모두 타입 이름을 예약어로 남겨 두기 때문이며, 이름을 바꾸고 난 뒤에는
  배포되는 텍스트에서 가장 큰 몫을 남기는 부류가 바로 타입 이름입니다. 자기 선언
  몫을 스스로 갚지 못하는 표기는 건너뛰므로, 한 번만 쓰이는 `mat4x3<f32>`는 그대로
  둡니다. 별칭 이름은 다른 곳에서는 전혀 쓰이지 않는 표기에서만 골라 씁니다. GLSL의
  `#define`은 텍스트 치환이고 모듈 전체에 걸리므로, 살아 있는 식별자를 잘못 붙잡으면
  안 되기 때문입니다. 정밀도 한정자(`precision highp float;`)를 지닌 타입은 절대로
  바꿔 쓰지 않습니다. 이 패스는 토큰 오프셋 단위로 잘라 끼워 넣으므로 `minify()`와
  어느 순서로 두어도 함께 동작하며, 나머지 서식은 그대로 둡니다. `type → alias`
  관계를 `mangle()`이 채우는 것과 같은 `renames` 맵에 보고하므로, 맵 하나로 둘 다
  해독할 수 있습니다.
- **`decodeShaderLog(log, renames)`**: 그 맵을 실제로 사용하는 절반입니다. 생성된
  텍스트는 일부러 알아보기 어렵게 되어 있어서, 배포된 드라이버 오류는
  `no matching overload in 'b' for arg of type 'l'`처럼 나타나는데, 이 함수는 이를
  다시 `terrain_shade`와 `vec2<f32>`로 되돌립니다. 치환은 토큰 단위로 이루어지므로
  드라이버 자체의 설명 문구, 줄 번호, 소스 발췌는 그대로 남습니다. 유일하게 되돌릴
  수 있는 이름(모듈 범위 이름, 타입 별칭처럼 드라이버가 실제로 이름 붙이는 대상)은
  그대로 치환되고, 함수 범위 이름은 여러 함수에서 일부러 재사용되므로 여러 후보로
  되돌아가는 이름은 추측 대신 후보를 함께 달아 보여줍니다
  (`f⟨coordinate (in noise) | tint (in shade)⟩`). `invertRenames(renames)`는 같은
  표를 데이터로 그대로 꺼내 줍니다. `renames`와 이 디코더는 배포 번들 밖에 두어야
  하며, 둘 다 `/emit-prod`에 있습니다.
- **`obfuscate({ renames? })`**: 표준 프리셋으로 `[mangle(opts), prune(), aliasTypes(opts), minify({ numbers: 'f32' })]`을
  묶습니다. 이를 `{ plugins }`에 그대로 펼쳐 넣고 `parens: 'minimal'`과 짝지으면
  배포되는 셰이더를 가장 작게 만들 수 있습니다. 예제 코퍼스 전체를 기준으로 이 네
  축을 모두 적용하면 일반 생성 결과 186_527자가 100_296자로, **−46.2%**로
  줄어듭니다.

플러그인은 Vite처럼 단계별로 실행됩니다. 배열 순서대로 모든 플러그인의
`transformIR`(IR 단계)이 먼저 실행되어 모듈을 조립한 뒤에, 모든 플러그인의
`transformText`(텍스트 단계)가 배열 순서대로 실행됩니다. 그래서 (둘 다 IR
단계인) `inline()`과 `mangle()`은 나열한 순서대로 합성되고, (둘 다 텍스트
단계인) `aliasTypes()`와 `minify()`보다 앞서 실행되며, 이 둘끼리도 배열
순서대로 합성됩니다.

**"prod는 dev를 최적화한 것"이라는 주장 검증**: 같은 플러그인 배열을
`semanticDiff`에 `transforms`로 넘기면, 선언한 파이프라인이 실제로 일으켰다고
증명할 수 있는 차이만 네 버킷에서 `explained`로 옮겨지며, 각 항목은 플러그인
이름과 버킷, 그리고 근거가 된 코드 줄(#1806)을 함께 답니다.

```ts
const d = semanticDiff(devModule, prodModule, { transforms: [inline(), ...obfuscate()] })
isSemanticallyEqual(d) // true ⇔ prod differs from dev ONLY as the declared pipeline dictates
d.explained // [{ transform: 'inline', bucket: 'controlFlow', line: '…' }, …]
```

분류 기준은 오직 구성적입니다. 선언한 플러그인 자체의 `transformIR`을 dev
쪽에 실제로 적용했을 때 그 줄이 diff에서 사라지는 경우에만 `explained`로
옮겨집니다. 겉모습만 최적화 결과처럼 보이는 회귀는 원래 버킷에 그대로
남으므로, dev↔prod 패리티 게이트는 설명되지 않은 나머지 차이만 예산으로
잡으면 됩니다. 텍스트 단계 플러그인은 아무것도 설명하지 못합니다. 비교기가
생성된 텍스트를 아예 보지 못하기 때문이며, 그래서 텍스트 플러그인을 포함해
프로덕션 배열 전체를 선언해도 안전합니다.

**ABI 경계: 절대로 이름을 바꾸지 않는 대상**: 진입점 이름(WebGPU의
`entryPoint`), **진입점 매개변수 이름**, `_fp64` 가드를 포함한 바인딩
이름(호스트가 이름으로 리소스를 찾기 때문입니다), 바인딩 구조체 이름(GLSL
UBO 블록 태그), 구조체 필드 이름(std140 배치와 GLSL의 varying이 이름으로
버텍스와 프래그먼트를 연결합니다)이 여기에 해당합니다. `reflect()`를 쓰는
호스트는 바뀌지 않은 그대로 바인딩합니다. 모듈 안에 `raw` 문이 하나라도
있으면 모듈 전체에서 mangle이 아무 일도 하지 않습니다. 텍스트로 남긴 참조는
이름 바꾸기 쪽에서 보이지 않기 때문입니다.

진입점 매개변수가 이 목록에 들어 있는 이유는, 구조체가 아닌 매개변수 하나가
그 자체로 GLSL varying 이름이기 때문입니다. 프래그먼트 쪽은 `inName(p.name)`으로
그 이름을 적고, 버텍스 쪽은 같은 varying을 반환 구조체의 필드 이름으로
적는데, 이는 별도의 생성 호출에서 이루어집니다. 한쪽만 이름을 바꾸면 아무
데도 연결되지 않습니다. 헬퍼 함수의 매개변수는 이런 식으로 읽는 쪽이 없으므로
이름을 바꿉니다.

렌더링 가능한 모든 예제는 `playground/e2e/_emit-obfuscate-gate.spec.ts`를
통해 실제 Tint와 ANGLE에서 `obfuscate()`를 거쳐 컴파일되고 픽셀 단위로
비교됩니다. 그리고 `examples/minify-safety.test.ts`는 예제 코퍼스 전체에
걸쳐 압축기 자신의 성질, 즉 압축 전후로 토큰 스트림과 모든 리터럴 값이 그대로
유지되고 이 패스가 멱등이라는 성질을 검증합니다.
