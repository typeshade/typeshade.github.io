## 1. Direction and principles

**Method: brand platform → visual principles (GTM §3.1/§3.3), each stated as a rule a reviewer can check.** Archetype **Sage** (the authority whose claim is evidence), secondary **Craftsman**. The page is a bench: a near-black chassis, hairline-ruled, on which the product's own output is mounted as **specimens** and every claim is a **readout**.

1. **The live shader is the only chroma that moves; the page is the only chroma that measures.** The accent is warm and the palette provably is not (M-3), so **warm = measured, cool = rendered, neutral = chrome** — a rule a reader learns in three seconds, and the reason no accent mark can be misread as shader spill.
2. **Legibility over moving media is an invariant, not a sweep result.** INV-1 and INV-2 (§4) are DOM assertions and every floor is solved against a **hypothetical pure-white frame** — the upper bound of any frame the shader can produce — so NFR-4's 80-frame sweep can only confirm. A design whose legibility is discovered by sweep is wrong between sweeps.
3. **The scrim must contain measured shader, or it is a black bar.** M-2 puts 100 % of the lit pixels in x 30–70 %, so §4 ends the scrim at **65.5 %**, inside the orb field, and §10 gates the luminance actually visible there.
4. **Proof is typography.** Every number is real text with its unit and condition adjacent, so a chip linearises in the order it reads. Nothing carrying a fact is an image, a tooltip or a colour.
5. **One shape, ten proofs — the plate:** surface step + 1 px frame + a 32 px bezel carrying a mono label and a state marker. Code frame, emit card, all five mounts, the diagnostic, the layout table, the disclosure and the install row are the same object. The full-bleed hero has no box of its own, so **its caption plate *is* its bezel** and carries the state marker — no mount is exempt. Never used for prose.
6. **One flourish per block, from three primitives only — hairline, tick, plate — and every instance draws build-time data.** A flourish that is not a measurement is not shipped.
7. **Depth is a surface step reinforced by a hairline; the system ships no shadow.** #080A14 → #0C1018 is four sRGB levels, so the hairline is what makes the step *visible* on a cheap panel — but the step, the heading and the section rhythm are what *carry* the boundary, which is why `line-1` is decorative and 1.4.11 does not reach it (§8). The one rule that does carry a boundary is the specimen frame, and it is `line-2` inside a ground mat (§5). The only `box-shadow` on the page is the focus ring — a stroke wearing a shadow's syntax.
8. **Zero decorative motion, and every accessibility preference may only raise the floor it governs.** I-14 permits an 8 px rise; this system spends none of it, because a measured number that fades in reads as a marketing device — the argument NFR-9 already makes about counters. Meanwhile `prefers-contrast`, `prefers-reduced-transparency` and `forced-colors` each move to a state the gate has already cleared, and §2 prints the computed ratio of **every** overridden token in **both** preference states.

**Refused by name**, so a later addition is declined without re-arguing: node-graph or material imagery · sliders, play/pause or a backend toggle near any canvas (G3) · a logo band (SP §14) · a comparison table (P10) · a second wording for any destination (R-15) · a `✓` or green tick asserting a gate passed for *this* build (R-4) · `text-transform: uppercase` on any string containing an identifier, file name or version.

## 2. Tokens

**Method: two-layer token set.** Design decisions go in Tailwind's `@theme` (they generate utilities); composition geometry — scrims, grid, focus, z — goes in `:root`, because a gradient is not a utility and must not become one. ## 3. Typography

**Method: modular below 32 px (r = 1.125, anchored at 16), a 4-px display ladder above** — the ladder, its raw steps and its reconciliation with the IA's ratified 72/56/52/44/36/20/18/17/14 are in §2's `@theme`. Two rules bound it: **17 px is the mobile end of the `--text-lead` clamp, not a step**, and nothing sets 17 as a fixed size any more — the nav wordmark, the one element that did, is 16/600 at every width; and **12.5 px is the only mono size on the page**, pinned by `codeFontSize` (the install command's 14 px is dropped — M-5 shows 14 px mono is no wider than 12.5, so it buys nothing). **Font metrics of record**, measured: Inter `0` advance **0.630 em** (1 ch = 0.63 × size); Geist Mono **7.0 px/char at 11 px** and **8.0 px/char at 12.5 px** (M-5), before tracking.

## 4. Layout, spacing and the hero composition

**Method: 8-pt grid, 12-column container, hero geometry derived from measured shader energy (M-2).** **Every gap, pad and offset inside a component is a multiple of 8**, with **three named 4-px optical exceptions and no others**: the state chip's `padding-block: 4px` (8 makes it a button, not a chip), the `padding-block: 4px` on tertiary / rail-route / `BR.SOURCE` / footer links (8 makes a footer column a quarter taller), and the `→` glyph's leading space. **Exempt by kind — strokes and shapes, which are not space:** every border and rule width, `--radius-*`, the focus ring's 2/4/5, the 6 px state-marker dot, the 4 px `line-3` square, the 10 px chevron, the 12 px tick. **Two page-level values are ratified by the IA's own drawings and are the only 4-px units outside a component:** `--gutter-x: 20px` at 390 (content 350) and `--nav-h-mobile: 52px`. **Section rhythm** (`padding-block`, ≥ 64rem / < 64rem): rail 56/40 · write, agree, types, precision **128**/96 · recognise 112/88 · adopt **160**/112 · footer 72/56 — two values plus one close, against the IA's five, because a five-value rhythm is one a reader cannot perceive and a maintainer must remember. **Inside a block:** `h2` → body 24 · body → proof 48/32 · proof → micro-label 16 · micro-label → CTA 32. **Inside the rail, which has no body:** `h2` → chips 32 · chip sentence → route link 12 · chips → `RAIL.COMMIT` 32.

**The line that is easy to miss and expensive to get wrong:** forced colours drop the scrim gradients entirely, and canvas pixels are **not** suppressed — so the composited hero would leave the headline sitting on raw shader. `--hero-stacked` is therefore a real switch read by a style query and written by both the `< 40rem` media query and the forced-colors block, which makes hero legibility a property of `Canvas` rather than of a gradient; before this it was a flag nothing consumed and the stated fix did not happen. **`B4.CANVAS`'s split bezel collapses to the single `data-label` row under forced colours**, exactly as the frame's `::after` already does — asserting a left/right correspondence to an image that is not drawn is the same false positional claim `--b4-split` exists to prevent. **And with no JS (I-16)** every proof is still server-rendered — snippet, diagnostic, layout table, emit card, every number, and every caption's backend-neutral build-time string; only the canvases and the copy button are lost, the button is `hidden` without JS and `B5.INSTALL` stays selectable text, so **the page's whole argument survives with zero canvases.**
